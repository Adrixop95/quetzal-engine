Task: honest playthrough framework. The maintainer wants 100 percent playthrough scenarios of every mission, played through the real input and command path of the clone (not forced script states), run again and again to catch path-finding, economy, transport and AI problems. Build the framework, on top of the existing playtest runner (--script, tests/playtest, --capture-dir, virtual time, headless and Xvfb modes):
1. High-level playthrough commands that resolve to the same player commands the UI issues: select by type or group or object id, train N units of a type at a building, build a building at a tile (with the usual placement rules), harvest or gather orders, attack-move, move, right-click context actions (board ferry, unload, attack), group assign and recall, wait until a condition (money at least N, unit count at least N, tile reached, objective flag, tick) with a timeout, and checkpoints that assert expectations. Keep the existing low-level click commands.
2. A runner `tools/playthrough.py` (or in the engine, your choice) that runs a scenario for a mission headless, writes a report (JSON and Markdown under work/playthrough/reports, git-ignored) with outcome (won, lost, timeout, scenario-failed), ticks, and anomaly detections: units that did not reach their goal within a bound, units standing still while holding an order (stuck), repeated path failures, passengers lost, transports destroyed, economy stalls (no income for N ticks), orders ignored, objects left idle, and any engine warning or unsupported action. Each anomaly records tick, object, position and a short reason, and with --capture-every it saves captures for them.
3. A synthetic demo scenario on a generated map covering the whole loop (build, train, harvest, group move through a narrow passage, ferry crossing, win condition) that runs in CI-suitable time, with tests; it must fail loudly when an order does not complete, so it proves the detectors work.
4. Documentation docs/playthrough_framework.md: the command set, the report format, how to write and replay a scenario, how to add detectors, and how mission scenarios stay private.
