# Sprite and animation mapping (state of work)

Data: `docs/data/sprites_mapping.json` (ids and offsets only, no pixels; generated by `tools/sprmap.py json game work/zt_all/heap.bin OUT`).
Contents: `types` (90 UGI types: kind, param, anim ids, raw descriptor record), `anims` (112 non-empty Anim items, per slot: start index, header frame, frames),
`sprites` (header facts per used sprite id: w, h, flags, palette id, cell size, ox, oy, for body 0x44c and shadow 0x454).
C++ reader: `src/engine/data/sprites.hpp` (+ generated `type_anims.hpp`). `SpriteDb::sprite_for(type, state, dir, tick)` and `AnimSet`.
Eyeball sheets: `tools/sprmap.py sheet GAME OUTDIR [type...]` (rows = slots, columns = frames).

## Verified (from decompiled code + data + sheet render)
- Anim item: `Anim`, u32 version 3, u32 slot[128] at +8 (start frame index, 0 = absent), 32-byte frames from +0x208. A sequence ends at a frame with sprite 0.
  The frame before a sequence start is a header frame; its field [2] is a looping sound while the state is active.
- Frame fields: `[0]` sprite id, `[1]` light id (light.xbe 0x455, muzzle glow; virtual +0x70), `[2]` sound id on first tick of the frame, `[3]` fire-weapon flag,
  `[4],[5]` dx, dy added to the unit position per tick (lunges, death slides), `[6]` y offset (virtual +0x18, added to draw position), `[7]` duration in ticks (12/s; 0 = hold).
- Sprite id in a frame indexes Res/Units.xbe group 0x44c (body, flags 6/1/64; flag 0x40 = palette-indexed RLE with alpha, NOT 16-bit colour, see src/core/sprite_alpha.hpp) and the same id in 0x454 (shadow, flags 14, translucent). Both are drawn by the view:
  shadow first, then body. Top-left draw position = object position - (sprite.ox, sprite.oy) (hotspot, header +0x14/+0x16) minus view origin (the +ox form in the first commit was wrong; verified against screenshots: 7 of 8 Marine-kind idle units matched pixel-wise with this and the right frame). Whether frame[6] adds to y is untested for ground units (always 0 there).
- Sprite header: +4 w, +6 h, +8 flags, +0xc u16 palette id, +0x10/+0x12 cell size, +0x14/+0x16 ox/oy. Palette id < 4 means team palette: Pal.xbe number = id + 0x10 + teamcolor*4
  (from View code at 0x465a50; team colour = side object +8). Palette ids >= 4 are fixed palettes. Shade level comes from a per-tile light map (not decoded).
- Type -> anim id from descriptor tables (valid after init): Marine 0x4ac430 stride 0x4c; Spider 0x4ae378/0x4c (anims rec[0], rec[2]); Building 0x49b538/0x508 (rec[0], 200..216, 300..316, 400..416);
  Zeppelin 0x4bcd00/0x44; Truck 0x4bc738/0x44; Bird 0x49b370/0x58; Headtruck 0x4ab2b0/0x50 (rec[0] body, rec[2] weapon); Defence 0x4aa3b0/0x110 (rec[0], rec[2]); Cannon 0x4a8e18/0x40;
  Boat anim 23 fixed; Johnka anim 29 fixed; Camera none. Table of all 90 types: `type_anims.hpp`.
- Marine convention (kind 0, anims 1..30; code 0x433db0/0x433820/0x433960): state 1 idle = slot 0, frame index = direction; state 2 move = slot dir+1 (loop);
  state 3 attack = slot dir+9 (one shot, fire flag in frame[3]); state 4 dying = slot 17 + rand%3; state 5 fidget = slot 20 + rand%3 (idle timer 60..259 ticks, only if slot exists);
  slot 23 = icon frames. Direction = ((angle+0x10)>>5)&7, angle 0 = east, 0x40 = up (counter-clockwise), from FUN_00461ac0.
- Sheet render of FOOTMAN confirms slots 0, 1-8 (walk), 9-16 (attack), 17-19 (death, fading corpse), 20-22, 23.

## Update 2: verified on screenshots (tools/zspr_run.sh + zspr_verify.py / zspr_scan.py)
- Screen origin of the view for a map whose side-0 Start is (sx,sy): world px minus (sx*48-298, sy*48-300) (unclamped case). Units idle shade ~10 matched best (lightmap based, not exact).
- Marine kind idle: sprite = anim slot 0 frame[dir], dir = object field +0x80 (verified on 8 types; match 0.5-0.9 given shading).
- Catapult (kind 4, anim 10): object +0x74 = angle (0..255); idle frame = slot 0 frame ((angle+4)>>3)&31 (32 directions, verified).
- Headtruck (kind 6, e.g. types 3,4,8,9,58,59,61,62): body anim (rec[0], anims 14/17) uses slot ((bodyAngle+4)>>3 & 31) + 1, bodyAngle = object +0x78; the weapon anim (rec[2], 50..54) idle uses slot 1 frame ((turretAngle+4)>>3 & 31),
  turretAngle = object +0x7c; firing uses weapon slot dir32+2; back to slot 0 frame dir32 afterwards. Both verified pixel-exact (score 1.00) for 9 types. Pos fixed-point at +0x70/+0x74 (px<<8), px also at +0x24/+0x28.
- Initial facing: Marine kind random (_rand&7); Headtruck and Truck random angle (&0xff).

## Update 3 (verified unless marked)
- Team colour: Pal number = header palette id + 0x10 + 4 * Color, Color = the `Color=` value of the owning [Side] in the .mp (tested Color=3: all 9 Marine-kind units matched pixel-exact at 1.00 with team 3, ~0.75 with teams 0-2). Palette ids >= 4 are fixed (no team colour).
- Unit shade: palette shade level 10 matched exactly at start-of-mission lighting (daylight keys of the map; the engine agent handles time-of-day separately).
- Direction labels: 9/9 Marine-kind units: sprite = slot 0 frame[dir] with dir = object +0x80; 0 = east, counter-clockwise (1 = NE, 2 = N, ...), confirmed visually and by pixel match.
- Zeppelin (kind 3, anim 5): idle slot 0 frame dir32 (angle at obj+0x70), screen y = pos.y - altitude (obj+0x7c): 1.00 match. Zeppelin2 (anim 26) same structure (match poor, probably lighting).
- Spider (kind 1): weapon anim (rec[2], 50/54) slot 1 frame dir32 of the turret angle byte (obj+0x92): 1.00 match (both spider types). Body anim 22: slot 0 = 1 frame (idle, sprite matched 0.63-0.77), slots 1-8 = 8-frame leg cycle per dir8, slot 9 = 20-frame (special/attack) -- slots 1-9 not pixel-checked.
- Hopcannon (kind 9, anim 28): slot 0 = 32 frames (direction), slots 1-8 8 frames, 9-16 3 frames, 17 4 frames; idle matched slot 0 frame 0 (0.99; facing 0).
- Defence (kind 7, anims 214..416): built tower = slot 1 frame 0 (0.88-1.00); turret anim slot 1 frame dir32 (angle obj+0x84) 1.00 for types 23, 81. Hypno tower (414) and crossbow tower (315) show direction frames inside slot 1 of the base anim (not decoded).
- Building (kind 2): placed buildings (state obj+0x68 = 2) show slot 1 frame 0 (0.93-0.98 on Town/Fortress/Village/Forpost). Slot 0 (5 one-tick frames) = construction stages: tick seek = ((T+1)*hp/maxhp)-1, nothing drawn when 0 (code 0x410c30). Slot 6 overlay is the `+0x2c` third sprite while state == 1. Slot 7 (4 or 8 frames) = UI icon frames (`+0x80`). Slot 5 (8-11 frames) used by destruction/work (not decoded). Low-HP fire: decoration anims 154/155/156 (10 frames, `Decoration` class via 0x4189d0(pos, side, animId, slot, loop)) at damage levels, sounds 0x97-0x99.
- Projectile/effect anims seen with 32 slots (one per dir32): 100, 101, 102, 109, 111, 112, 157, 158 (3-10 frames each; anim 100 slot 32 = 11-frame impact). Effects: 105 (30-frame translucent ring), 113 (20 one-frame variants), 150-152 (explosion frames), 154-156 (fire, 10 frames); decoration ids used by code: 0x69, 0x6b, 0x71-0x74, 0x96-0x9d. The class behind each is not decoded; sheets via `tools/sprmap.py animsheet GAME OUT id...`.
- Slot structure per Marine-kind anim (all 1..30 except 22): 0 idle(8 frames), 1-8 walk (4-10 frames per dir), 9-16 attack (2-19 frames), 17-19 die (3-25 frames, lingering corpse 26-234 ticks total), 20-22 fidget/special (4-25 frames), 23 icon (4 frames).
- Tools: `tools/zspr_run.sh NAME TYPES OUTDIR` (private game dir, own map, objscan+heapdump), `tools/zspr_verify.py` (Marine-kind direction/palette check), `tools/zspr_scan.py` (best matching slot/frame per object).
