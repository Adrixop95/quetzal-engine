## Method to name a word

Each kind reads its descriptor through a pointer stored in the object (for example Marine
`+0x68`, Bird `+0x6c`, Zeppelin `+0x64`). Every use of the word appears in the decompiled code
as `*(int *)(*(int *)(obj + PTR) + OFF)` or through the kind's virtual accessors. List all use
sites of each offset in `work/decomp/all_full.c` (private), read the surrounding code, and
record the meaning with the function address. Known examples: Marine `+0x1c` weapon id,
`+0x2c` category byte 0, `+0x2e` category byte 2 (Hypno), `+0x30` and `+0x34` armor values
returned by the object virtuals `+0x108` and `+0x10c`, Bird dword 9 weapon id, Zeppelin
dword 8 weapon id.

Descriptor offsets read through field `+0x64` (number of functions reading each): `+0x14`(2)

example the build tree and production lists inside the Building record) and need the
containing functions read as tables, not as single offsets.

Building words that carry data come in runs: words 0 to 5 (named), 15 to 18, 21 to 40, 42 to
46, 55 to 56, 59 to 74 and the pointer words 320 and 321. The runs 21 to 40 and 59 to 74 look
like small integer arrays (placement and footprint flags, production and upgrade entries); name
them by reading the loops that index them (build tree and production code), not single offsets.
So the work to take the descriptor tables to 99 percent is the naming of about 158 words, not
about 450.
