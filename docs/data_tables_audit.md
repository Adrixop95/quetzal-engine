# Data table completeness audit (2026-11-09)

Goal: reach 99% of the original's data tables (type descriptors, weapon records, build tree,
economy tables) with every word named and labelled V (read from code) or G (guess).
Source: `docs/data/rules.json` (generated by `tools/build_rules.py` from `docs/data/*.csv`).

## What is complete

  time and development level.

  survey (`docs/weapon_class_map.md`) the record layout of classes 0, 1, 2, 3, 6, 7, 8, 9, 10, 11,
  12 and 13 is read from code; the rules file still marks classes 0, 3, 7, 9 and 11 as guess or
  unread and must be updated from that document.

## Method to name a word

Each kind reads its descriptor through a pointer stored in the object (for example Marine
`+0x68`, Bird `+0x6c`, Zeppelin `+0x64`). Every use of the word appears in the decompiled code
as `*(int *)(*(int *)(obj + PTR) + OFF)` or through the kind's virtual accessors. List all use
sites of each offset in `work/decomp/all_full.c` (private), read the surrounding code, and
record the meaning with the function address. Known examples: Marine `+0x1c` weapon id,
`+0x2c` category byte 0, `+0x2e` category byte 2 (Hypno), `+0x30` and `+0x34` armor values
returned by the object virtuals `+0x108` and `+0x10c`, Bird dword 9 weapon id, Zeppelin
dword 8 weapon id.
