# Rules and type data (partial status)

Numeric tables: `docs/data/*.csv`, generated by `python3 -I tools/extract_rules.py [work/heapdump.bin]`
(static tables from `Aztec.exe` + descriptors populated at game startup, read from a `heapdump`).

## Verified (from code and table reads)
- **Prices and build times** (Town.cpp, static data printed by dump function `0x45ba56`): `UnitPrices[90]` @0x4bc3e8, `BuildTime[90]` @0x4bc550
  (static, in the exe file). `DevLevel[90]` @0x515580 is calculated in the Town constructor (0x459490) by function `0x45c780` from the build tree
  (0 = basic types, 1 = farm/mine and similar, increases with the number of required buildings, 10 = unavailable; types 82..89 = 10). File: `types.csv`.
- **Multipliers** (`town_factors.csv`): `Ktime[3] = 2, 1, 0.667`, `Kprice[3] = 0.667, 1, 2` (index = town BuildSpeed, Town+0x158),
  `KWarehouse = 1.0, 1.333`, `KAdvPostTime = 1.5`? (see note below), `KAdvPostPrice = 1.0`.
  Price (`Town::Price` 0x45c5b0, called during purchases via 0x45a426 -> TakeMoney 0x447d00) = `ftol(UnitPrices[t] * K * f + 0.5)`, time (`Town::Time` 0x45c690) = `ftol(BuildTime[t] * K' * f' + 0.5)` (NOTE: an earlier version of this file had these two functions swapped), `f = 1.0`, or `0.8` if the town's side is
  computer-controlled and is not an enemy of everyone (`0x43d2c0` + `0x447320`). Rounding: `+ constant from 0x494838` (0.5) and `__ftol`.
  NOTE: the order of KAdvPost* is sometimes reversed when reading the dump; check 0x45c5b0/0x45c690 (time uses 0x4bc3e4/0x4bc3e0 depending on the branch).
  The same function provides the price/time in the UI tooltip ("Price: %i Time: %i", 0x441ef6), so this is the price visible to the player.
- **Build tree** (`buildtree.csv`, table 0x4af130: 3 races x 4 town hall types x 33 entries x 34 dwords; town hall: 0 outpost, 1 village, 2 town,
  3 fortress; `townhall_ids.csv`). Entry: dword0 = type (bit 0x4000000 = "build on map", i.e. a building; absent = train a unit);
  subsequent dwords = required buildings (bit 0x8000000 = building of another race/"advanced", e.g. DEMOLISHER requires LABS; RUS TRUCK_FLAMETHROWER
  requires a captured AZT_WORKSHOP). End of list: 0xffffffff or >= 0x5a. Read by: BuildTree.cpp (0x411890 copies the race's tree, 0x45c780 calculates DevLevel).
- **Type descriptors** (tables in `.data`, populated by startup code; `desc_*.csv`, columns = dwords d0..):
  Marine 0x4ac430 x0x4c (16), Building 0x49b538 x0x508 (32), Defence 0x4aa3b0 x0x110 (9), Headtruck 0x4ab2b0 x0x50 (8), Truck 0x4bc738 x0x44 (1),
  Spider 0x4ae378 x0x4c (2), Zeppelin 0x4bcd00 x0x44 (2), Bird 0x49b370 x0x58 (3), Cannon 0x4a8e18 x0x40 (1). Index = parameter from `types.csv`.
  Object field `+0x68` (Marine) / `+0x64` (Building, Bird, Zeppelin) / `+0x6c` (Defence, Headtruck, Spider) points to the descriptor.
- **Marine** (`Marine::Think` 0x433db0): d0 = animation ID; d1 = initial HP (also the regeneration threshold in one state), d2 = HP regeneration per tick,
  d3 = regeneration threshold in the other state, d4 = maximum HP; d5 = arrival radius/movement step in px per tick (movement: 8.8 position += vector, arrival when distance <= d5);
  d7 = weapon ID (index into `0x515ac0[]`, -1 = none; `Marine+0xa8` returns the weapon object); d12..d14 = 8.8 multipliers (256 = 1.0), meaning undetermined
  (resistance: d12 fire, d13 physical, d14 -; confirmed by reading the methods).
- **Building** (0x40fb70): d0 = animation ID, d1 = HP (e.g. 30000), d2/d3 = offset, d4/d5 = size (px); d0xf8 != 0 creates a firing object
  (FUN_0042afe0), d0x100 = weapon ID or -1; d0x104..0x128 = increasing thresholds (1000, 2050, 3100...; farms only: RUS_FARM param 7, AZT_FARM param 20,
  probably income/production levels). Remaining fields: undetermined.
- **Weapons** (Weapon.cpp): `wep_NewWeapon(owner, id)` (0x46d900) selects a class according to table `0x494d30[id] = (class 0..13, parameter)` (`weapons_ids.csv`, IDs 1..59,
  prototype objects in `0x515ac0[]` created with owner = NULL in 0x470780). Weapon virtual methods: `+0x5c` damage (attacker, target), `+0x60` reload time,
  `+0x78` CanFire. `wep_CalcKillTime` (0x46fac0) = `ceil(target_HP / damage) * reload_time` (target HP: vcall +0x38, or, if the attacker has flag +0xf8: +0x78).
  Class data tables (`weapon_class_*.csv`; record size from `lea` in constructors, record counts and field meanings UNVERIFIED):
  class0 @0x48f868 x20, class1 (Arrow) @0x48f408 x64, class3 (Axe) @0x48f750 x24, class7 @0x494218 x36, class9 @0x493f60 x32, class12 @0x4906f0 x12,
  classes 2/13 @0x494a90 x0x38, class8 @0x4ae448 x16. Classes 4,5,6,10,11 have no parameter table. In class 1, field d12 = secondary weapon ID (explosion).
- **Side** (Side, 0x69c): `+0x698` cash, `+0x63c` total earned (`AddMoney` 0x4477d0), `+0x640` total spent (`TakeMoney` 0x447d00:
  refuses if cash < amount), `0x447d30` = CanAfford. `+0x648/0x64c/0x650` side bitmasks: ally / enemy / neutral
  (`0x447320` = isEnemy(x): x = -1 -> no neutrals/allies; x == own index -> false).
- **BUILD command** (PCT 0x1c, tick 0x4577b0): finds the entry in the town's tree (`0x45cec0`), checks it (`0x45cd50`), places the building (`0x410960`/`0x41d6a0`);
  building HP increases in field +0x38 during construction (`Building` 0x410c30/0x410cc0).

## Experimentally verified (zstat/zspd/zdl/zeco test masks, tools `tools/make_zstat.py`, `zstat_run.sh`, `zstat_speedmaps.sh`, `zstat_duels.py`)
Added `RT_UNIT_LOG=file` (+`RT_UNIT_EVERY=n`) to `runtime/oracle.c`: every n ticks, logs lines `U frame addr type side(-1) x y hp maxhp +0x64` for objects from pool 0x4cc3d0 and `S frame side money spent earned`.
Note: the first 90 objects in the pool are type prototypes (x=y=-1000, +0x38 = initial building HP: e.g. CHI_WATCHTOWER 17500, RUS_WATCH_TOWER 20000, RUS_FORTRESS_TOWER 40000).
- **Movement speed** (`docs/data/speed_measured.csv`, 864 px in a straight line, tick = 1 logic step): Marine = `d5` px/tick (average ~ d5 + 0.1..0.3 due to 8.8 rounding: FOOTMAN 9.26, KNIGHT 15.3, JAGUAR 16.4, BEAR 5.08);
  Headtruck = `d7` (TRUCK_AXE 9, CANNON 6, FLAME 6, KATUSHA 5, WHEEL_KATUSHA 7, WHEEL_FIRE 8, WHEEL_AXE 11, WHEEL_CROSSBOW 8); Spider = `d7` (4); Zeppelin = `d5` (8 and 9); Truck/Catapult = `d5` (8).
  Birds (Bird `d5` = 12/18/15?) fly along arcs, unmeasured. Tick = 1/12 s.
- **Marine HP regeneration**: +`d2` HP per tick (8 for FOOTMAN), up to the threshold (`d1`/`d3`, see above); confirmed in the HP log (+8 every tick).
- **Infantry damage** (duels, `docs/data/duel_damage.csv`; noisy data, many duels without hits/a target): FOOTMAN 600 every 10 ticks (weapon entries: ID 4 = class 2 param 0, record (9,600,..) -> damage `d1`=600, reload time `d0`+1=10),
  against vehicles (f0) x0.5 = 300 (multiplier rec[6]=128), ARCHER 800 every ~19 (ID 14 = Arrow param 1: `d4`=800, `d2`=12 reload+flight), RIFLEMAN 1600 every 27, MAGE 2600 every ~23.
- **Class 2/13 damage formula** (record 0x494a90 + 0x38*param; `0x46dfe0`): `dmg = rec[1]`; successively multiplied by `rec[k]/256` (>>8 after each multiplication) if the target is: airborne (vcall 0xa4) -> rec[5], non-organic (0xf0) -> rec[6], 0xf4 -> rec[7], 0xe8 -> rec[8], a structure (0xec) -> rec[9];
  then `dmg += rec[2] * target_armor(vcall 0x10c) / 256`. Reload time `rec[0]`(+1 tick when firing), range `rec[4]`.
- **Class 1 formula (Arrow, record 0x48f408 + 0x38*param, `0x403d00`)**: `dmg = rec[4]` multiplied analogously (airborne rec[7]; 0xf0 rec[8]; 0xf4 rec[9]; 0xe8 rec[10]; 0xec rec[11]) + (if airborne and rec[7]==0 -> 0 for the armor component) `rec[5]*armor(0x10c)/256` + damage from secondary weapon `rec[12]` (weapon ID). `rec[1]`=projectile speed, `rec[2]`=reload time, `rec[3]`=range (px).
- **Other classes**: 0 (Ball) = damage from weapon `rec[4]`; 4/5: 3000 (1500 vs 0xf0/0xec; 0 vs ally or airborne); 6: 18000 (9000 vs 0xf0; 0 vs airborne); 10: 1800 (1125 vs 0xf0/0xec; x1.25 vs 0xf4/0xe8; 0 vs airborne); 9 (rec 0x493f60 + 32*param): `rec[0]` multiplied by (airborne rec[3], 0xf0 rec[4], 0xf4 rec[5], 0xe8 rec[6], 0xec rec[7]) + `rec[1]*armor/256`;
  11 (FireThrow): `10 * f(0x429f60)`, reload time 40; 12: sum of damage from two weapons `rec[0]`,`rec[1]`; 8: damage from weapon `rec[0]`.
- **Target categories** (virtual methods): 0xa4 = airborne (Zeppelin, Bird only); 0xf0 = vehicle/building/non-organic object (not Marine, Zeppelin, Bird); 0xec = structure (Building, Defence); 0xe8/0xf4 = Marine flag `d11` byte 1 (0xf4 = its negation); 0xf8 = `d11` byte 2 (HYPNO only). Marine armor: `d12` = vcall 0x108 (fire), `d13` = 0x10c (physical: arrows, axes), `d14` = 0x110; 256 = 1.0.
- **Building**: descriptor +0x18..+0xdc = 7x7 occupancy grid (value 2 = occupied) relative to the building's tile (`Building::0x411230`); HP in the prototype = `d1` (+0x04).
- **Income**: `AddMoney` called from `0x4111af` (destruction/cycle of a building with a Harvest object +0x70: `(list_value) * Town::0x45c450(building)` (KWarehouse 1.0 / 1.333 depending on warehouse 0x12,0x28,0x46)); Harvest object (16 B): +4 list, +8 increment per tick (8.8, `rec[0xf8] * 2.56`), +0xc accumulator.
- **AI spending** (map `zeco1`, Rus AI, 5000 gold, `BuildSpeed` 0/1 and `Difficulty` 0/50/100/200 have no effect): FOOTMAN costs 161 every 56 ticks (!), RUS_WORKSHOP 961, TRUCK_AXE 361, RUS_MINE 121; i.e. buildings/machines `0.8*UnitPrices + 1`, but a footman costs 161 instead of 81: UNEXPLAINED (probably an additional TakeMoney when the unit spawns). Passive AI income +60/300 ticks recorded in `earned`.
