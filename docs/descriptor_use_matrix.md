# Descriptor use matrix

Coverage of the current independent engine, audited against `descriptor_fields.md`,
`descriptor_provenance.md`, `descriptor_config_cells.md`,
`descriptor_building_defence.md`, `descriptor_other_kinds.md` and `data/rules.json`.
The latest shared layout supplies V/G labels when older prose differs. V verifies
a read or layout; it does not establish complete gameplay semantics or parity.

Every one of the 520 layout words is listed, including all 201 data-bearing
columns, constant -1 sentinels and all-zero capacity. **Yes** means a typed loader
consumer or behavior consumer exists; **loader only** explicitly means that the
value is available in `TypeRules` but does not yet drive that subsystem.
**No** means deliberately ignored: G fields, unread words and guest name pointers.
`unused` is the source status for unread words, rather than a V/G interpretation.

Locations below are relative to `src/engine/`. `sim/rules.cpp::load_dir` consumes
`desc_*.csv`, not JSON at runtime; the JSON/CSV layout documents the same words.
An array entry is consumed only when its schedule count enables it. Footprint
values equal to 2 occupy tiles; value 1 receives no invented margin semantics.

Auxiliary armour is a verified accessor with no identified damage consumer and is
loaded without applying resistance. Bird `organic_flag` is presentation metadata,
not a new damage-category predicate. Sound lists and turret variant indices are
loaded without inventing event timing or unknown animation-entry semantics.
Headtruck/Spider/Cannon turn steps are loaded; their full firing/turn integration
remains open. Marine and Defence combat animation lookup uses descriptor resource
IDs; the general renderer still uses its established static type metadata.

Defence d63 has a verified read but a G height interpretation. It is ignored;
projectiles retain an explicit zero-height engine fallback for Defence. Name
pointer words are never dereferenced or reinterpreted as ordinals. Localized UI
names use `ui/names.cpp::type_name_ordinal` and the user string table independently.

Price, build time, development, production lists and prerequisites are **not
descriptor words**. Existing `sim/rules.cpp::load_dir` loads `types.csv` price/time/
development and `buildtree.csv` prerequisites; `production_value` and
`sim/game_sim.cpp` use them for adjusted prices, payment and construction/queues.
Weapon speed/range/reload likewise belong to weapon tables. `weapon_impl`,
`visual_weapon`, `attack` and `GameSim` already consume their established getters;
no object word is repurposed as a range, price or capacity.

## Validation and limits

`tests/test_descriptor_use.cpp` writes invented records for all nine families,
checks distinct primary/secondary HP, regeneration thresholds, armour channels,
speed, weapon range/reload, costs, Defence metadata, bounds, occupancy and enabled
schedules, and initializes simulation objects. It changes auxiliary armour, the
G word and guest-pointer noise to ensure they do not alter damage or install a
launch height. `tests/test_combat.cpp` supplies invented animation banks and
verifies descriptor-selected resources, explicit zero, missing resources and
attack timing. `tests/test_descriptor_fields.py` checks exhaustive matrix coverage.

No original executable, reference runtime or private data was used. Synthetic
checks establish engine contracts only. Unresolved consumers, sound-event timing,
general renderer integration and reference behavior comparisons remain open.
